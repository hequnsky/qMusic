## 1. 技术选型

### 1.1 Android 客户端

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | Kotlin 1.9+ | 官方推荐，协程友好 |
| UI | Jetpack Compose (BOM 2024+) | 声明式 UI，Material 3 |
| 播放引擎 | Media3 (ExoPlayer) 1.3+ | 支持网络音频、前台服务、通知栏控制 |
| 网络 | Retrofit 2.11 + OkHttp 4.12 + Kotlin Serialization | REST 客户端 |
| JSON | kotlinx.serialization | 类型安全的 JSON 解析 |
| 图片 | Coil 2.6 | Compose 图片加载（AsyncImage） |
| 本地存储 | Room 2.6 | 收藏、最近播放持久化 |
| 架构 | MVVM + Repository | 单一数据源，单向数据流 |
| 依赖注入 | Hilt 2.51 | 简化依赖管理（可选，按需） |
| 构建 | Gradle 8.13 + AGP 8.5 + Kotlin 2.0 | 模块化配置 |

> 为降低示例复杂度，本项目**不引入 Hilt**，采用手动构造 + `Application` 容器管理依赖。

### 1.2 服务端（音乐抓取服务）

服务端由两个进程组成：Node 网关（对外统一入口）+ 多音源聚合服务（Go）。

| 项 | 选型 |
| --- | --- |
| 运行时（网关） | Node.js 16+（实测 24 可用） |
| 依赖（网关） | `NeteaseCloudMusicApi@4.32.0`（Express + axios + crypto-js） |
| 运行时（多音源） | Go 1.26（`server/musiclib-service`，基于 [guohuiyuan/music-lib](https://github.com/guohuiyuan/music-lib)，AGPL-3.0） |
| 职责 | 抓取/代理第三方音乐平台公开接口，统一输出 JSON 与音频流 |
| 端口 | 3000 网关 / 3001 网易云上游 / 3100 多音源服务（均可通过环境变量覆盖） |

**多音源支持矩阵**（`server/musiclib-service`）：netease、qq、kugou、kuwo、migu、qianqian、soda、bilibili、apple 共 9 个音源。
其中 7/9 可直接播放（qq/kuwo 受上游风控限制），音频以 HTTP Range 回源（返回 206）支持拖动进度条，soda、migu(Z3D) 走解密链路。

## 2. 系统架构

```
┌────────────────────────────┐        ┌──────────────────────────────────────────┐
│        Android App         │  HTTP  │           Node 网关 (:3000)               │
│ ┌────────────────────────┐ │ ────▶ │ ┌──────────────────────────────────────┐ │
│ │ UI (Jetpack Compose)   │ │ ◀──── │ │ /search /song/url /lyric /personalized│ │
│ │  发现/播放/搜索/我的    │ │ JSON  │ │ /toplist /playlist ...                │ │
│ ├────────────────────────┤ │       │ └───────────────┬──────────────────────┘ │
│ │ ViewModel (MVVM)      │ │       └─────────────────┼────────────────────────┘
│ ├────────────────────────┤ │                         │ 透传 /api/*
│ │ Repository            │ │       ┌─────────────────▼────────────────────────┐
│ ├────────────────────────┤ │       │  网易云上游 (:3001)  │  多音源服务 (:3100) │
│ │ Media3 PlayerService  │ │       │  NeteaseCloudMusicApi │  music-lib (Go)   │
│ │ Room (收藏/历史)        │ │       └───────────────────────┬──────────────────┘
│ └────────────────────────┘ │                               │ HTTP（抓取 / Range）
└────────────────────────────┘       ┌───────────────────────▼──────────────────┐
                                     │ 第三方音乐平台公开接口                      │
                                     │ 网易云/QQ/酷狗/酷我/咪咕/千千/汽水/B站/Apple │
                                     └──────────────────────────────────────────┘
```

**多音源路由**：客户端在搜索页切换音源时，向 `/search` 附带 `source` 参数；网关按 `source` 将该次请求转发到多音源服务（`/api/search?source=...`）或走网易云上游。歌曲播放地址同理（`/song/url?source=...`），多音源服务对音频流做 Range 透传并处理平台加密格式。

**数据流（以「搜索并播放」为例）**：
1. UI 输入关键词 → `SearchViewModel.search(keyword)`
2. `MusicRepository.searchSong()` → Retrofit 调用服务端 `/search`
3. 服务端返回歌曲列表（含 `id/name/artist/album/picUrl`）
4. 点击歌曲 → `PlayerViewModel.play(song)`：
   - 调用 `/song/url?id=` 获取真实播放地址（mp3）
   - 调用 `/lyric?id=` 获取 LRC 歌词（异步、失败可忽略）
   - `Media3` 加载播放地址开始播放
5. 播放状态通过 `StateFlow` 驱动 UI（进度/播放态/歌词高亮）。

## 3. 服务端接口规格

服务基于 `NeteaseCloudMusicApi`，本项目实际使用的接口如下。

### 3.1 搜索
```
GET /search?keywords=海阔天空&limit=30&offset=0
```
响应（节选）：
```json
{
  "result": {
    "songs": [
      {
        "id": 347230,
        "name": "海阔天空",
        "artists": [{ "id": 11111, "name": "Beyond" }],
        "album": { "id": 22222, "name": "海阔天空", "picUrl": "https://..." },
        "duration": 450350
      }
    ]
  }
}
```

### 3.2 歌曲播放地址
```
GET /song/url?id=347230&level=standard
```
响应：
```json
{
  "data": [{
    "id": 347230,
    "url": "http://m702.music.126.net/.../xxx.mp3",
    "br": 128008,
    "type": "mp3",
    "time": 45035,
    "size": 721023
  }]
}
```

### 3.3 歌词
```
GET /lyric?id=347230
```
响应：
```json
{
  "lrc": { "lyric": "[00:00.000] 作词 : 黄家驹\n[00:18.466]今天我 寒夜里看雪飘过\n..." },
  "tlyric": { "lyric": "" }
}
```

### 3.4 每日推荐（发现页 Hero）
```
GET /personalized?limit=1
```
响应：`{ "result": [{ "id": 歌单id, "name": "全民热播...", "picUrl": "...", "playCount": 12345 }] }`
> 说明：`/personalized` 返回推荐歌单。发现页 Hero 也可使用 `GET /recommend/songs`（需登录态，本示例以歌单封面/名称代替，保证无账号可用）。

### 3.5 热门歌单（发现页横向卡片）
```
GET /top/playlist?limit=10&order=hot
```
响应：`{ "playlists": [{ "id": 18271967084, "name": "欧美R&B...", "coverImgUrl": "...", "trackCount": 98, "playCount": 123456 }] }`

### 3.6 歌单详情
```
GET /playlist/detail?id=18271967084
```
响应：`{ "playlist": { "id": ..., "name": "...", "tracks": [ { "id":..., "name":..., "ar":[{"name":"..."}], "al":{"name":"...","picUrl":"..."}, "dt": 250066 } ] } }`

### 3.7 服务端部署
```bash
# ① 网易云上游（:3001）
cd server && npm install && PORT=3001 npm start

# ② 多音源服务（:3100，Go，基于 music-lib）
cd server/musiclib-service && ./build.sh && ./qmusic-musiclib

# ③ 网关（:3000，对外统一入口）
cd server && npm start
```
- 环境变量：`UPSTREAM_NETEASE=http://127.0.0.1:3001`、`UPSTREAM_MULTI=http://127.0.0.1:3100`
- 模拟器访问宿主机：`http://10.0.2.2:3000`
- 真机调试：`http://<电脑局域网IP>:3000`，或用 `adb reverse tcp:3000 tcp:3000` + `http://127.0.0.1:3000`
- Go 依赖经 GOPROXY 拉取（国内建议 `https://goproxy.cn,direct`）

### 3.8 版本与产物命名规范

| 项 | 规则 |
| --- | --- |
| 版本号 | `MAJOR.MINOR` 两位小数，**每次发版 MINOR +0.01**（1.00 → 1.01 → 1.02 …） |
| versionName | 与版本号一致，如 `1.02` |
| versionCode | **整数版本号，每次 +1**（1.01 → 101、1.02 → 102），必须单调递增 |
| APK 产物名 | `qMusic-<版本号>-<构建类型>.apk`，如 `qMusic-1.02-release.apk` |
| 归档位置 | `android/dist/`（随版本累积，不覆盖历史版本） |
| 变更说明 | 每版必须在 `docs/CHANGELOG.md` 新增一节，含「现象 / 根因 / 修复 / 验证」四要素 |

版本号集中在 `android/version.properties` 维护，打包脚本会自动递增：

```properties
appName=qMusic       # APK 文件名前缀（自定义打包名字）
versionName=1.02     # 每次打包自动 +0.01
versionCode=102      # 每次打包自动 +1
```

```bash
node scripts/bump-version.js        # 递增 versionName/versionCode 后写回 version.properties
./gradlew assembleRelease           # 产物名由 androidComponents.onVariants 自动生成
```

`app/build.gradle.kts` 读取上述属性并注入 `versionName` / `versionCode` / `BuildConfig.APP_DISPLAY_NAME`，
再由 `androidComponents.onVariants { ... outputFileName }` 统一命名产物，无需手工重命名。

## 5. 数据模型

### 5.1 远程模型（kotlinx.serialization）

```kotlin
@Serializable
data class Song(
    val id: Long,
    val name: String,
    val artists: List<Artist> = emptyList(),
    val album: Album? = null,
    val duration: Long? = null,
    val picUrl: String? = null,     // 冗余封面，便于列表
)

@Serializable
data class Artist(val id: Long, val name: String)

@Serializable
data class Album(val id: Long, val name: String, val picUrl: String? = null)

@Serializable
data class SongUrl(val id: Long, val url: String?, val br: Long? = null, val type: String? = null)

@Serializable
data class LyricResult(val lrc: Lrc?, val tlyric: Lrc? = null)
@Serializable
data class Lrc(val lyric: String = "")

@Serializable
data class Playlist(
    val id: Long,
    val name: String,
    val coverImgUrl: String? = null,
    val trackCount: Int = 0,
    val playCount: Long = 0,
)
```

### 5.2 本地模型（Room Entity）

数据库版本 **v2**（v1 → v2 迁移：收藏/历史各新增 `source`、`token` 两列，用于记录歌曲来自哪个音源以及该音源所需的临时 token，迁移默认回填 `netease`）。

```kotlin
@Entity(tableName = "favorites")
data class Favorite(
    @PrimaryKey val songId: Long,      // stableSongId：FNV-1a 64 位哈希，跨音源稳定
    val name: String,
    val artist: String,
    val album: String,
    val picUrl: String?,
    val durationMs: Long,
    val source: String = "netease",    // 音源标识
    val token: String? = null,         // 音源临时 token（部分平台播放地址需要）
    val addedAt: Long = System.currentTimeMillis(),
)

@Entity(tableName = "history")
data class History(
    @PrimaryKey val songId: Long,
    val name: String,
    val artist: String,
    val album: String,
    val picUrl: String?,
    val durationMs: Long,
    val source: String = "netease",
    val token: String? = null,
    val playedAt: Long = System.currentTimeMillis(),
)
```

> `songId` 由 `stableSongId(source, id)` 计算（FNV-1a 64 位），保证同一首歌在不同音源下 ID 稳定、且与网易云数字 ID 不冲突，避免跨音源收藏互相覆盖。

## 6. 播放模块设计

### 6.1 PlayerController
- 封装 `ExoPlayer`，暴露 `StateFlow<PlayerUiState>`（歌曲、进度、播放态、歌词）。
- 方法：`play(song)`, `toggle()`, `next()`, `prev()`, `seekTo()`, `setQueue(list, index)`。
- 歌词加载：播放时异步请求 `/lyric`，解析 LRC 为 `List<LyricLine>`，随进度推进高亮当前行。

### 6.2 PlayerService（前台服务）
- 继承 `MediaSessionService`（Media3），管理 `MediaSession` 与 `ExoPlayer`。
- 通知栏：封面（Coil 加载 Bitmap）、歌名/歌手、播放暂停/上一首/下一首。
- `onTaskRemoved` 停止播放；`onDestroy` 释放播放器。

### 6.3 播放地址注意事项
- 服务端返回的歌曲 URL 为 `http://`（明文），因此 Android 需要：
  - `AndroidManifest.xml` 设置 `android:usesCleartextTraffic="true"` 或
  - `res/xml/network_security_config.xml` 仅对 `10.0.2.2` 与局域网 IP 放行明文。
- 本项目采用 **network_security_config** 白名单方案，更安全。

### 8.1 构建命令
```bash
cd android
```

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 第三方音乐接口变动 | 播放地址失效 | 服务端独立部署，可替换为其他平台源；歌曲 URL 失败时自动重试 |
| 版权/平台限制 | 部分歌曲无法播放 | 仅用于学习；UI 层做加载失败提示 |
| 明文 HTTP 被系统拦截 | 播放失败 | network_security_config 白名单 + 后续可切换 HTTPS 代理 |
| 模拟器网络 | 无法访问宿主机 | 使用 `10.0.2.2` 特殊地址 |
| 多音源上游风控（qq/kuwo） | 该音源搜索或播放返回空/403 | 音源可切换，默认回退网易云；网关对失败音源返回空列表而非报错 |
| 多音源服务未启动 | 切到非网易云音源时无结果 | 网关探测上游健康，失败时降级到网易云并在响应头标注 |
| 音频流为分片/加密（soda、migu Z3D） | 拖动进度条失败 | 服务端解密后按 HTTP Range 透传，返回 206 Partial Content |
| 音源 token 过期 | 收藏的歌曲二次播放失败 | 持久化 `source`+`token`，播放前重新解析地址；失败时提示重试 |
