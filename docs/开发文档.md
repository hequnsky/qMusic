## 2. 系统架构

```
┌────────────────────────────┐        ┌───────────────────────────────┐
│        Android App         │  HTTP  │   Node 音乐抓取服务 (:3000)     │
│ ┌────────────────────────┐ │ ────▶ │ ┌───────────────────────────┐ │
│ │ UI (Jetpack Compose)   │ │ ◀──── │ │ NeteaseCloudMusicApi     │ │
│ │  发现/播放/搜索/我的    │ │ JSON  │ │  /search /song/url /lyric │ │
│ ├────────────────────────┤ │       │ │  /personalized /歌单... │ │
│ │ ViewModel (MVVM)      │ │       │ └───────────────────────────┘ │
│ ├────────────────────────┤ │       └──────────────┬────────────────┘
│ │ Repository            │ │                      │ HTTP（抓取）
│ ├────────────────────────┤ │       ┌────────────▼────────────────┐
│ │ Media3 PlayerService  │ │       │ 第三方音乐平台公开接口           │
│ │ Room (收藏/历史)        │ │       │ （网易云等）                │
│ └────────────────────────┘ │       └───────────────────────────────┘
└────────────────────────────┘
```

**数据流（以「搜索并播放」为例）**：
1. UI 输入关键词 → `SearchViewModel.search(keyword)`
2. `MusicRepository.searchSong()` → Retrofit 调用服务端 `/search`
3. 服务端返回歌曲列表（含 `id/name/artist/album/picUrl`）
4. 点击歌曲 → `PlayerViewModel.play(song)`：
   - 调用 `/song/url?id=` 获取真实播放地址（mp3）
   - 调用 `/lyric?id=` 获取 LRC 歌词（异步、失败可忽略）
   - `Media3` 加载播放地址开始播放
5. 播放状态通过 `StateFlow` 驱动 UI（进度/播放态/歌词高亮）。

## 3. 服务端接口规格

服务基于 `NeteaseCloudMusicApi`，本项目实际使用的接口如下。

### 3.1 搜索
```
GET /search?keywords=海阔天空&limit=30&offset=0
```
响应（节选）：
```json
{
  "result": {
    "songs": [
      {
        "id": 347230,
        "name": "海阔天空",
        "artists": [{ "id": 11111, "name": "Beyond" }],
        "album": { "id": 22222, "name": "海阔天空", "picUrl": "https://..." },
        "duration": 450350
      }
    ]
  }
}
```

### 3.2 歌曲播放地址
```
GET /song/url?id=347230&level=standard
```
响应：
```json
{
  "data": [{
    "id": 347230,
    "url": "http://m702.music.126.net/.../xxx.mp3",
    "br": 128008,
    "type": "mp3",
    "time": 45035,
    "size": 721023
  }]
}
```

### 3.3 歌词
```
GET /lyric?id=347230
```
响应：
```json
{
  "lrc": { "lyric": "[00:00.000] 作词 : 黄家驹\n[00:18.466]今天我 寒夜里看雪飘过\n..." },
  "tlyric": { "lyric": "" }
}
```

### 3.4 每日推荐（发现页 Hero）
```
GET /personalized?limit=1
```
响应：`{ "result": [{ "id": 歌单id, "name": "全民热播...", "picUrl": "...", "playCount": 12345 }] }`
> 说明：`/personalized` 返回推荐歌单。发现页 Hero 也可使用 `GET /recommend/songs`（需登录态，本示例以歌单封面/名称代替，保证无账号可用）。

### 3.5 热门歌单（发现页横向卡片）
```
GET /top/playlist?limit=10&order=hot
```
响应：`{ "playlists": [{ "id": 18271967084, "name": "欧美R&B...", "coverImgUrl": "...", "trackCount": 98, "playCount": 123456 }] }`

### 3.6 歌单详情
```
GET /playlist/detail?id=18271967084
```
响应：`{ "playlist": { "id": ..., "name": "...", "tracks": [ { "id":..., "name":..., "ar":[{"name":"..."}], "al":{"name":"...","picUrl":"..."}, "dt": 250066 } ] } }`

### 3.7 服务端部署
```bash
cd server
npm install
npm start        # 监听 0.0.0.0:3000
```
- 模拟器访问宿主机：`http://10.0.2.2:3000`
- 真机调试：`http://<电脑局域网IP>:3000`

### 4.2 分层职责

| 层 | 职责 | 关键类 |
| --- | --- | --- |
| UI 层 | 渲染 Compose 页面，转发用户事件 | `DiscoverScreen`, `PlayerScreen`, `SearchScreen`, `MineScreen` |
| 表现层 | 持有 UI 状态（StateFlow），调用用例 | `DiscoverViewModel`, `PlayerViewModel`, `SearchViewModel` |
| 数据层 | 远程 API + 本地 Room 的统一入口 | `MusicRepository` |
| 播放层 | 播放控制、前台服务、通知 | `PlayerController`, `PlayerService` |

### 4.3 依赖注入（轻量容器）

`QMusicApp` 持有 `MusicRepository`、`PlayerController` 等单例；ViewModel 通过 `viewModelFactory` 获取依赖。不引入 Hilt，减少构建复杂度。

## 5. 数据模型

### 5.1 远程模型（kotlinx.serialization）

```kotlin
@Serializable
data class Song(
    val id: Long,
    val name: String,
    val artists: List<Artist> = emptyList(),
    val album: Album? = null,
    val duration: Long? = null,
    val picUrl: String? = null,     // 冗余封面，便于列表
)

@Serializable
data class Artist(val id: Long, val name: String)

@Serializable
data class Album(val id: Long, val name: String, val picUrl: String? = null)

@Serializable
data class SongUrl(val id: Long, val url: String?, val br: Long? = null, val type: String? = null)

@Serializable
data class LyricResult(val lrc: Lrc?, val tlyric: Lrc? = null)
@Serializable
data class Lrc(val lyric: String = "")

@Serializable
data class Playlist(
    val id: Long,
    val name: String,
    val coverImgUrl: String? = null,
    val trackCount: Int = 0,
    val playCount: Long = 0,
)
```

## 6. 播放模块设计

### 6.1 PlayerController
- 封装 `ExoPlayer`，暴露 `StateFlow<PlayerUiState>`（歌曲、进度、播放态、歌词）。
- 方法：`play(song)`, `toggle()`, `next()`, `prev()`, `seekTo()`, `setQueue(list, index)`。
- 歌词加载：播放时异步请求 `/lyric`，解析 LRC 为 `List<LyricLine>`，随进度推进高亮当前行。

### 6.2 PlayerService（前台服务）
- 继承 `MediaSessionService`（Media3），管理 `MediaSession` 与 `ExoPlayer`。
- 通知栏：封面（Coil 加载 Bitmap）、歌名/歌手、播放暂停/上一首/下一首。
- `onTaskRemoved` 停止播放；`onDestroy` 释放播放器。

### 6.3 播放地址注意事项
- 服务端返回的歌曲 URL 为 `http://`（明文），因此 Android 需要：
  - `AndroidManifest.xml` 设置 `android:usesCleartextTraffic="true"` 或
  - `res/xml/network_security_config.xml` 仅对 `10.0.2.2` 与局域网 IP 放行明文。
- 本项目采用 **network_security_config** 白名单方案，更安全。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 第三方音乐接口变动 | 播放地址失效 | 服务端独立部署，可替换为其他平台源；歌曲 URL 失败时自动重试 |
| 版权/平台限制 | 部分歌曲无法播放 | 仅用于学习；UI 层做加载失败提示 |
| 明文 HTTP 被系统拦截 | 播放失败 | network_security_config 白名单 + 后续可切换 HTTPS 代理 |
| 模拟器网络 | 无法访问宿主机 | 使用 `10.0.2.2` 特殊地址 |
