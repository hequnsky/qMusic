# qMusic 更新日志（CHANGELOG）

本文件记录**每一个版本**的变更。规则如下：

| 项 | 规则 |
| --- | --- |
| `versionName` | 展示版本号，**每次打包 +0.01**（1.01 → 1.02 → 1.03 …） |
| `versionCode` | 应用市场的整数版本号，**每次打包 +1** |
| APK 文件名 | `<自定义名字>-<versionName>-<buildType>.apk`，例如 `qMusic-1.01-release.apk` |
| 配置文件 | [`android/version.properties`](../android/version.properties) |
| 自动递增 | `android/scripts/bump-version.js`（打包脚本会自动调用） |
| 一键打包 | `android/build-apk.bat`（Windows）/ `android/build-apk.sh`（macOS/Linux） |

> 打包流程会**先自增版本号再编译**，所以每个 APK 的版本号天然唯一，
> 装到手机上可以直接用「关于」里的版本号对上是哪一次构建。

## [1.19] — 2026-10-23

> 服务端「全挂了」故障排查与恢复：Cloudflare 临时隧道被回收、本机 3000/3001 端口被其它会话的预览服务占用、多音源进程退出。服务栈迁到 3300/3301，App 内置地址同步更新。

### 1. 故障现象

- 用户反馈「GitHub 地址挂了、服务端挂了」：App 打开显示「加载失败，请确认音乐服务已启动」，线上域名无法访问。
- 排查结论：**GitHub 仓库本身正常**（`api.github.com` 200、Release 下载 302 正常），实际是三个服务端问题叠加。

### 2. 三个根因

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 线上域名 `albums-quite-grass-harvest.trycloudflare.com` 打不开 | Cloudflare Quick Tunnel 会话被回收，日志 `Unauthorized: Tunnel not found`，其后持续 `timeout: no recent network activity` |
| 2 | App 拿到 HTML 而非 JSON | 本机 `:3000` / `:3001` 被**其它 WorkBuddy 会话启动的静态预览服务**（`node server.js`，任何路径 fallback 到 index.html）占用，qMusic 网关实际未运行 |
| 3 | 多音源不可用（`/multi/sources` → `available:false`） | `:3100` 的 `qmusic-musiclib` 进程已退出（后台启动方式被回收） |

### 3. 改法

- **服务端迁移端口**：网关 `3000 → 3300`、网易云上游 `3001 → 3301`，多音源保持 `3100`；启动命令：
  `PORT=3300 NCM_PORT=3301 MUSICLIB_URL=http://127.0.0.1:3100 node index.js`（避开与其它项目的端口冲突）。
- **App 默认地址端口同步**：`ServerConfig.DEBUG_BASE_URL` / `RELEASE_BASE_URL` 的 `:3000` → `:3300`；
  debug 包调试命令相应改为 `adb reverse tcp:3300 tcp:3300`。
- **线上地址更新**：`ONLINE_BASE_URL` 指向新隧道 `https://zealand-bureau-very-san.trycloudflare.com/`。
- **多音源改为受管后台任务**重启，避免子 shell 退出导致进程被回收。

### 4. 验证

- 本地 `:3300` 四接口：`/personalized` 200、`/search` 200、`/song/url` 200、`/multi/sources` → `available:true`（9 个音源）。
- 公网新域名同样四项全 200（含多音源可用）。
- release 包真机安装冷启动，主页内容完整加载。

### 5. 遗留问题

- Quick Tunnel 域名**每次重启都会变化**，且匿名隧道会被回收——这是「服务端反复挂」的根本原因。
  彻底解法是 `render.yaml` + `server/Dockerfile` 部署到 Render（固定域名、7×24 在线），代码已就绪待部署。

## [1.17] — 2026-10-14

> 登录方式改造（移除二维码，改手机号 + 密码）、登录页穿透点击修复、主题新增「暗夜黑」且选择面板改为等大框滑动列表、播放页图标重绘、重命名弹框自动聚焦、全页面虚拟返回键 inset 适配。

### 1. 移除二维码登录，改手机号 + 密码登录

- **根因/背景**：原二维码登录依赖「手机网易云 App 扫码」第二台设备，模拟器/无网易云 App 的用户无法登录；且轮询链路长（getQrKey → createQr → 每 2s checkQr）。
- **改法**：改用网易云 weapi 网页云接口 `/login/cellphone`（服务端 `login_cellphone` 模块负责 MD5，失败时返回网易云原始错误信息）。App 侧新增 `MusicApiService.loginCellphone` / `MusicRepository.loginCellphone`，删除全部二维码链路（`qrKey` / `qrCreate` / `qrCheck` 及 `QrKeyResponse` 等 5 个数据模型）。登录成功后仍走 `user/account` 回填 userId。
- **UI**：登录页重写为「手机号 + 密码」表单：11 位数字过滤、密码视觉变换、软键盘 Done 直接提交、错误红字 + 输入框 supportingText、登录中转圈。

### 2. 修复登录页还能点到「我的」页底部按钮

- **根因**：登录页原本是 `MineScreen` 内容区里的普通 `Column`，而底部导航栏在外层 `MainScreen` 的 `Scaffold(bottomBar=)` 上、z 序更高——登录页根本盖不住它，底部「发现 / 播放 / 我的」照常可点。
- **改法**：登录页改为**全屏 Dialog** 包裹打开（`Dialog(properties = DialogProperties(usePlatformDefaultWidth = false, dismissOnClickOutside = false))`）。Dialog 是独立 window，天然覆盖底部栏；系统返回键也会先关掉登录页而不是切走 tab。

### 3. 主题：新增「暗夜黑」+ 等大主题框滑动列表

- `ThemeStyle` 新增 `AMOLED("amoled", "暗夜黑")`：近纯黑背景（`#050507`）/ 卡片（`#101015`）专用配色 `AmoledQMusicColors`，OLED 屏更省电；强调色为中性银灰，与现有 5 套彩色深色主题区分。
- 主题选择面板（`ThemePickerDialog`）重写：每个主题框**固定 72dp 等高**（缩略图 44×56 固定尺寸），7 套主题一屏放不下时整列 `LazyColumn` 滑动；预览图对「暗夜黑」同步用近纯黑背景。

### 4. 播放页图标重绘

- **顺序播放按钮**：原 `PlaylistPlay` 图标与右侧「播放列表」（`QueueMusic`）过于相似、语义不明确 → 自绘 `res/drawable/ic_play_order.xml`（左侧三条渐短横线 = 列表，右下实心三角 = 播放），与随机 / 单曲循环形成明确区分。
- **底部操作行**：评论 / 下载 / 歌单 / 更多 原先用 emoji「•」占位 → 全部换成矢量图标（Comment / Download / PlaylistAdd / MoreHoriz），喜欢项用 Favorite / FavoriteBorder 描边-实心切换；`BottomActionItem` 的 `icon` 参数由 `String`(emoji) 改为 `ImageVector`。

### 5. 重命名歌单弹框自动获取焦点

- 重命名 / 新建歌单对话框的 `OutlinedTextField` 加 `FocusRequester` + `LaunchedEffect { withFrameNanos{}; requestFocus(); showKeyboard() }`（延迟一帧避开 Dialog window 焦点竞争）；请求失败时静默降级——输入框外框始终可见，点击即可输入。

### 6. 全页面虚拟返回键 inset 适配

- **视频页**（`VideoFeedScreen`）：底部作者信息原先 `bottom = 28.dp` 直接贴屏幕底，会被虚拟返回键区域压住 → 作者信息与右侧竖排操作栏均加 `navigationBarsPadding()`；视频画面本身保持全屏铺满。
- **登录页**：根 `Column` 加 `navigationBarsPadding() + imePadding()`（Dialog 窗口不会自动避开导航栏）。
- 其余二级页（播放页/歌词页/评论/下载/歌单/排行榜/分类/本地音乐等）此前已带 inset，本次全量核对无遗漏；底部导航栏（`QMusicBottomBar`）沿用 `Surface(navigationBarsPadding)`。

## [1.16] — 2026-10-14

> 新增三种播放模式：顺序播放 / 随机播放 / 单曲循环。替代原「列表循环」逻辑（原逻辑播完最后一首会循环回第一首，现顺序播放播完即停）。

### ✨ 新增：播放模式（顺序 / 随机 / 单曲循环）

- **入口**：播放页左下角模式按钮，点击循环切换：顺序播放 → 随机播放 → 单曲循环 → 顺序播放，并 Toast 提示当前模式。
- **三种模式行为**：
  - **顺序播放**：按队列顺序播放；当前曲播放结束自动进下一首；**播放到最后一首即停**（不再循环回第一首）。
  - **随机播放**：当前曲播放结束（或点「下一首」）时从队列随机选一首，尽量不重复当前曲。
  - **单曲循环**：当前曲播放结束后自动重播（seek 回 0 继续，不重复拉取播放地址）；「下一首」按钮仍可手动切歌。
- **持久化**：模式选择存入 SharedPreferences（`qmusic_playback`），杀进程重启后保持。
- **工程配置**：新增 `PlaybackMode` 枚举；`PlayerController` 的 `next()` / `onSongEnded()` 按模式分派；ExoPlayer 自身 `repeatMode` 固定为 OFF（队列是手动 `setMediaItem` 的，避免与单曲循环叠加）；`PlayerUiState.repeatMode` 改为 `playMode`。

### 涉及文件

- `player/PlayerController.kt`：`PlaybackMode` 枚举、`cyclePlayMode()`、`onSongEnded()`、`randomIndex()`、模式持久化
- `ui/player/PlayerScreen.kt`：模式按钮改为三态图标（播放列表/随机/单曲）+ Toast
- `ui/player/PlayerViewModel.kt`：`cycleRepeatMode()` → `cyclePlayMode()`
- `res/values/strings.xml`、`res/values-en/strings.xml`：新增 `play_mode_shuffle`、`play_mode_toast`

| 模式循环切换（顺序→随机→单曲→顺序） | ✅ |
| 顺序播放：歌末自动下一首 | ✅ |
| 顺序播放：队尾停止（不循环回第一首） | ✅ |
| 随机播放：连点 4 次下一首 → 队列 idx 15→8→18→12，无顺序规律且不重复 | ✅ |

## [1.13] — 2026-10-13

> 新增「导入歌单」：把文字（歌名 歌手）或外部歌单分享链接一键导入网易云账号，生成云端歌单。

### ✨ 新增：导入歌单

- **入口**：「我的」页功能网格新增「导入歌单」卡片（`我的歌单` 旁边）：
  - 未登录：点击直接引导去网易云二维码登录；
  - 已登录：弹出导入对话框。
- **两种导入方式**（Tab 切换）：
  - **文字导入**：每行一首「歌名 歌手」，如 `周杰伦 晴天`；
  - **链接导入**：每行一个歌单分享链接（支持 QQ 音乐等外部歌单链接）。
  - 可选填「歌单名」，留空则网易云自动取名。
- **流程**：提交 → 生成导入任务 → 每 2s 轮询任务状态（最多 60s）→ 显示成功/失败。
  - 成功后歌单直接出现在网易云账号里，可在网易云 App 查看。
- **实现**：
  - `MusicApiService` 新增 `playlistImportCreate` / `playlistImportStatus`（带 Cookie）；
  - `Models.kt` 新增 `PlaylistImportResponse` / `PlaylistImportStatusResponse` 等模型；
  - `MusicRepository` 新增 `importPlaylistByText` / `importPlaylistByLink` / `importPlaylistStatus`；
  - `MineScreen` 新增 `ImportPlaylistDialog`（文字/链接 Tab + 轮询）。

### ⚠️ 说明

- 该接口是网易云官方的歌单导入能力，**必须登录**网易云账号才能使用；

## [1.09] — 2026-10-11

> 歌词页：整块歌词沉到屏幕下方（1 条反馈）。

### 🐛 修复

- **歌词整块沉在屏幕下方，越唱越往下**
  - **根因：坐标口径混用。** `LazyListItemInfo.offset` 是**内容坐标**，`contentPadding` 已被平移掉。
    歌词列表上下各留半屏 `contentPadding`，真机实测 `viewportStartOffset = -1309`、
    `viewportSize = 2618` —— 视口顶端在内容坐标里是 **−1309，而不是 0**。
    旧实现直接拿 `viewportSize / 2` 当「视口中心」去减 `offset`（两种坐标混用），
    算出的 `delta` 恒为负，其含义是「向列表头部回滚」；
    而打开歌词页时列表正处于顶部（`canScrollBackward = false`），`scrollBy` **消耗 0** → 纹丝不动。
    于是歌词永远停在「未滚动」位置：唱到第 3 行时已落到屏幕约 66% 处，越唱越往下。
  - 改法：中心基准改用 `viewportStartOffset + viewportSize / 2`，
    「量出当前行在哪 → 差多少补多少」的相对纠正才第一次真正生效
    （实测一轮即收敛，日志 `final=0 ref=0`）。
  - 目标行还没进视口时先 `scrollToItem(target, 0)` 粗定位
    （内容坐标 0 恰好就是视口正中，粗定位即居中），
    再用最多 4 轮 `scrollBy` 收敛到 2px 以内，
    顺带吸收「当前行加粗放大」导致的行高变化。

### ✅ 真机验证（1240×2772，debug 包）

- 像素级检查：白色当前行垂直中心 **1309 = 视口中心，偏差 0px**；水平中心 **620** = 屏幕中线。
- 连续采样，播放推进 `currentLyricIndex` 2 → 4 → 5，每次偏差均为 **+0px**。
- 最终 release/debug 双包复测：连续两句
  「为寂寞的夜空画上一个月亮」→「把我画在那月亮下面歌唱」，
  同样 **+0px**、水平中心 620，**居中与逐行跟随都成立**。
- 校验产物见 `docs/screenshots/v109/`（`00-before-*.png` 为修复前，`01/02-centered*.png` 为修复后）。

    原版反而靠后（用户反馈的「以 DJ 为主」即由此而来）。
  - 修复：新增 `preferOriginals()` —— 对搜索结果做**稳定排序**，
    把含 `dj / remix / 翻唱 / 加速 / 慢摇 / 抖音 / 电音版` 的二次创作版本整体后移；
    不删除结果、不打乱同组内的原有顺序，原版与相关度高的条目自然上浮。

- **搜索页「热搜榜」的「更多 ›」点了完全没反应**（用户反馈的「热搜版更多没反应」）
  - 根因：`SectionTitle` 的 `onMore` 默认值是**空实现 `{}`**，而搜索页热搜榜这一处
    压根没接线 —— 「更多 ›」照样渲染出来，点了什么都不会发生。
  - 修复两处：
    1. `onMore` 改为可空：为 `null` 时**不渲染**「更多 ›」，
       从此不会再出现"看着能点、点了没反应"的假入口；
    2. 新增「完整热搜榜」页面（`HotSearchScreen`），走 `/search/hot/detail`
       取更全的榜单（约 20 条 + 热度值），点任意一条直接用该词搜索。

- **榜单区块的「更多 ›」经常点不中**
  - 根因：「更多」是**纯文字可点**，热区只有十几个 dp，而它紧贴屏幕右边缘
    （实测中心 x=1085，屏宽 1240），手指很难精确点中 —— 观感同样是「点了没反应」。
  - 修复：点击区域扩大到 `12dp 横向 + 6dp 纵向` 内边距的可点矩形，
    视觉大小保持不变。

- **发现页「换一换」点了没反应**
  - 现象：点「换一换」推荐内容完全不变。
  - 根因：**网易云 `/personalized` 在同一账号/IP 下返回顺序是固定的**
    （实测连续 5 次请求，首个歌单完全一致），而原实现每次都取
    `firstOrNull()`，等于重新请求了一遍同样的东西。
  - 修复：改为一次取回 10 个推荐歌单缓存为「歌单池」，
    「换一换」时在本地随机切到一个**与当前不同**的歌单并加载其歌曲。

- **搜索页看不到其他音乐源**
  - 现象：音源切换条不出现（只有网易云）。
  - 根因有两个：
    1. **运行中的网关是旧进程**，没有挂载 `/multi` 路由，
       所有多音源请求落到网易云服务上返回 404 —— 重启网关后恢复（9 个音源全部在线）；
    2. 客户端 `loadSources()` **只在 ViewModel 初始化时拉一次**，
       而 ViewModel 在 Tab 间切换时会被复用 ——
       「先开 App、后启多音源服务」的情况下音源条永远不会出现。
  - 修复：搜索页每次进入都重新探测一次可用音源。

### ✨ 变更

- **「我的」页改为入口 + 独立列表页**
  - 原来「我喜欢的」「最近播放」直接内嵌在「我的」页的同一个 `LazyColumn` 里，
    页面很长、首屏信息密度高。
  - 现在「我的」页只保留**入口卡片**（带歌曲数），
    点击进入独立列表页（`FavoriteSongsScreen` / `HistorySongsScreen`），
    页内可「播放全部」，点任意一行即从该行开始播放。

### 🔧 调试流程

- **调试统一使用 debug 包**：
  - `build-apk.sh debug` / `build-apk.bat debug` 一键出调试包；
  - **debug 包也使用 release 证书签名** —— debug 与 release 可互相覆盖安装，
    调试过程中不必卸载，本地收藏/歌单与桌面小组件都不会丢
    （本机没有 release keystore 时自动回落到默认 debug 证书）；
  - debug 包默认服务器地址改为 `http://127.0.0.1:3000/`，
    配合 `adb reverse tcp:3000 tcp:3000` 即可连本机服务，不依赖局域网 IP。

## [1.03] — 2026-10-11

> 本版聚焦**播放体验修复**与**本地歌单**能力落地，共 6 项。

### 🐛 修复

- **播放页点击标题 / 歌手会「重复播放」当前歌曲**
  - 现象：在播放页点歌曲名或歌手名，会听到当前歌曲从头重播一次。
  - 根因：**触摸事件穿透**。播放页根 `Box` 只设了背景，没有消费触摸事件，
    Compose 的命中测试因此穿透到下层的「发现」页歌曲行，触发了那一行的 `onPlay`。
    文字本身没有点击行为，所以看起来像「点标题 → 莫名其妙重播」。
  - 修复：给播放页根容器加一个**空的 `clickable`**（无涟漪、无回调），
    只用于吃掉落在空白区域的触摸，阻止事件继续向下传递。
    同时新写的歌词页 / 弹窗层同样自带 `BackHandler` 与触摸拦截。

- **歌词不会滚动 / 当前行不居中（部分歌曲）**
  - 现象：有的歌歌词整块挤在屏幕下方不动，当前唱到哪句看不出来。
  - 根因：三个问题叠加 ——
    1. 原实现给了上下各半屏的 `contentPadding`，却用 `animateScrollToItem(cur)`
       把目标行对齐到**列表内容顶部**（即被 contentPadding 顶到屏幕外面），
       当前行因此长期停在视口下半部分；
    2. 自动滚动自身会把 `isScrollInProgress` 置为 true，
       被当成「用户在拖拽」而触发 2 秒暂停跟随，形成**自己打断自己**；
    3. `currentLyricIndex` 为 -1 时（歌词未加载完 / 首句时间戳晚于当前进度）完全不滚。
  - 修复：改为按**像素偏移把当前行精确居中**（`视口中心 - 目标行中心`），
    并用独立的 `autoScrolling` 标志把「程序滚动」与「用户拖拽」区分开，
    程序滚动不再触发暂停；歌词未就绪时正确跳过。

- **主页按返回键会闪一下**
  - 根因：原 `BackHandler(enabled = selectedTab != 0)` 在主页时是**禁用**状态，
    系统回退走 Activity 默认退出动画，Compose 树先做一次无意义重组再退出。
  - 修复：主页同样接管返回键，直接 `finish()` 并把退出转场动画设为 0，
    消除那一下可见的中间态。

### ✨ 新增

- **本地歌单：创建 / 管理 / 播放页一键加入**
  - 数据层：新增 Room 表 `playlists` 与 `playlist_songs`（数据库 v2 → v3，含迁移），
    复合主键 `(playlistId, songId)` + 外键级联删除，重复加入天然幂等。
  - 播放页底部操作区新增「歌单」入口，弹出「添加到歌单」底部弹窗：
    可勾选 / 取消已有歌单，也可当场新建歌单并加入当前歌曲。
  - 「我的」页新增「我的歌单」入口：查看、重命名、删除歌单，
    点进歌单可查看曲目、播放全部、单曲移出。
  - 歌单里的歌曲保留 `source` / `token`，多音源歌曲从歌单播放同样能解析到正确地址。

- **播放页新增「下载」入口与「已下载」页入口**
  - 「下载」按钮：下载当前歌曲（已在下载中 / 已下载会给出对应提示）。
  - 底部操作区新增进入已下载列表的入口，可查看与管理本地下载。

### 🎨 优化

- **播放页进度条改细**
  - Material3 `Slider` 轨道偏粗，改为自绘 `ThinProgressBar`：
    视觉轨道 3dp、滑块 8dp，但保留 24dp 的点击热区，
    既纤细又不牺牲易点性，支持点击跳转与拖动擦洗。

### ✅ 测试

- Kotlin 全量编译通过；`assembleRelease` 产出 `qMusic-1.03-release.apk`。

## [1.02] — 2026-10-11

> 本轮为**真机批量测试**（10 轮 × 33 条断言，330/330 通过）驱动出的修复版本。
> 测试脚本：`android/scripts/batch-test.sh`，报告：`android/testing/report-rounds.md`。

### 🐛 修复

- **【严重】「我的」页点「我喜欢的 / 最近播放」卡片直接闪退**
  - 现象：进入「我的」页后点击这两个入口卡片，应用必崩，退回桌面。
  - 根因：`MineScreen` 里「我喜欢的」和「最近播放」是同一个 `LazyColumn` 下的
    两个 `itemsIndexed`，却共用了 `"$index-$songId"` 这套 key。
    只要同一首歌**同时出现在收藏和播放历史**里（几乎必然发生），
    就会产生两个相同的 key `0-5257138`，Compose 直接抛
    `IllegalArgumentException: Key "…" was already used`。
  - 修复：两段列表分别加上互不冲突的前缀（`fav-` / `his-`）。
  - 该 bug 属 Compose 的确定性崩溃，**冷启动后必现**，已回归验证。

- **封面全链路缺失（播放页唱片 / 通知栏 / 系统媒体控制中心 / 桌面小组件都只有占位图）**
  - 现象：默认音源（网易云）下播放任何歌曲，封面位置始终是灰色音符占位图；
    用户反馈的「媒体控制切歌图片不切换」实际是「图片压根没加载出来」。
  - 根因：网易云的 `search` / `search/suggest` 接口返回的歌曲只有
    `album.picId`（数字图片 ID），**不返回 `album.picUrl`**，
    于是 `Song.coverUrl` 恒为 `null`，MediaSession / 通知 / 小组件都拿不到图。
    （歌单详情、排行榜接口是有 `picUrl` 的，所以只有「搜索进来的歌」有问题。）
  - 修复：新增 `MusicRepository.enrichCovers()` —— 当结果里存在缺失封面的歌曲时，
    批量调用 `song/detail` 拿回 `al.picUrl` 再回填；
    全部已有封面时不产生任何额外请求，失败时静默降级不影响搜索本身。
    同时覆盖「搜索建议」下拉里的封面。
  - 验证方式：读取通知栏 `android.largeIcon` 是否非空，作为封面真正加载成功的客观判据。

### ✅ 测试
